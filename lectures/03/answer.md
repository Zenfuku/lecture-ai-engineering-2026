- 第1回（素のLLM）とエージェントの回答の違い：第1回の素のLLMは講座固有の用語集を参照できないのに対し、第3回のエージェントは用語集を検索したうえで、「基礎・実装・発展」の3レベルと、どれか1つに取り組めば宿題完了であることを回答した。
- `--trace` で見えたツール呼び出し（ツール名と引数）：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` がそれぞれ呼び出された。

## 宿題

- 取り組んだレベル：基礎
- やったこと：`app/tools.py` の `search_glossary` の docstring にある「query には調べたい用語を1つだけ入れる」という説明を、「複数の関連用語をまとめて入れてよい」に変更した。変更前後で同じ「LoRA と QLoRAの違いは？」という質問を `--trace` 付きで実行し、ツールの呼ばれ方を比較した。
- 結果：変更前は `search_glossary` が LoRA と QLoRA で2回呼ばれ、`tool_calls=2`、`input_tokens=1196` だった。変更後は `search_glossary({'query': 'LoRA QLoRA'})` と1回にまとめて呼ばれ、`tool_calls=1`、`input_tokens=893` となった。最終回答はどちらもLoRAとQLoRAの違いを説明できていた。
- 気づき・疑問：docstring の説明を1文変えただけで、モデルのツールの使い方や引数が変わることを確認できた。一方、変更後の検索結果ではLoRAの項目しか返っていないのに、最終回答ではQLoRAについても説明していた。ツール呼び出し回数を減らすと効率化できる一方で、必要な根拠を十分に取得できなくなる可能性もあり、効率と検索精度のバランスが重要だと感じた。
